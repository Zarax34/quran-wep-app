# PR-01: Database Migration & Password Hardening

## Description
This PR introduces the tooling and configuration changes required to migrate the Quran Center application from SQLite to MySQL. It also implements a password hardening strategy to convert plain-text or weak passwords to Bcrypt hashes.

## Changes
1.  **Configuration (`app.py`):**
    *   Updated `SQLALCHEMY_DATABASE_URI` to prioritize `DATABASE_URL` environment variable, falling back to SQLite.
    *   Made the default Admin user creation idempotent to prevent duplication/errors during migration re-runs.
2.  **Dependencies (`requirements.txt`):**
    *   Added `pymysql` (MySQL driver), `Flask-Migrate`, `alembic`, and `passlib[bcrypt]`.
3.  **Scripts (`scripts/`):**
    *   `migrate_sqlite_to_mysql.sh`: A Bash script using `sqlite3` CLI to dump data and `mysql` CLI to import it, with sanitization steps.
    *   `dump_sqlite_py.py`: A Python-based fallback dumper for environments without `sqlite3` CLI.
    *   `rehash_plain_passwords.py`: A script to detect weak passwords (heuristic) and rehash them using Bcrypt, marking a temporary `password_needs_rehash` flag.
4.  **Documentation:**
    *   `docker-compose.mysql.yml`: For local testing.

## How to Run (Migration)

### Prerequisites
*   Local MySQL instance (or use `docker-compose -f docker-compose.mysql.yml up -d`).
*   `sqlite3` CLI tool (or use python fallback).
*   `mysql` CLI tool.

### Steps
1.  **Stop the Application:** Ensure no writes are happening to the SQLite DB.
2.  **Run Migration Script:**
    ```bash
    # Usage: ./scripts/migrate_sqlite_to_mysql.sh [SQLITE_DB] [MYSQL_URI]
    ./scripts/migrate_sqlite_to_mysql.sh quran_center.db "mysql+pymysql://user:pass@localhost:3306/quran_center"
    ```
    *If you don't have sqlite3 CLI, use the python fallback first:*
    ```bash
    python3 scripts/dump_sqlite_py.py quran_center.db dump.sql
    mysql -u user -p quran_center < dump.sql
    # Then run rehash manually
    python3 scripts/rehash_plain_passwords.py "mysql+pymysql://user:pass@localhost:3306/quran_center"
    ```

3.  **Verify:**
    *   Check `docs/prs/PR-01-failures.log` if any password rehashes failed.
    *   Start the app with `DATABASE_URL` set to the MySQL URI.

## Rollback
If the migration fails or data is corrupt:
1.  Stop the application.
2.  Revert `DATABASE_URL` (unset it) to fall back to `sqlite:///quran_center.db`.
3.  The SQLite file remains untouched by the migration scripts (read-only dump).

## Downtime
The migration requires a downtime window during the Dump & Import phase. For the current dataset size, estimated window is < 10 minutes.
